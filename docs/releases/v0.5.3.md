# Sessionbus peers v0.5.3

This release requires Sessionbus daemon v0.5.7 and pins the Go SDK and JavaScript
kit at v0.5.7. Inbound lane messages wake an idle lane automatically. Active
Codex and Grok lanes preserve acknowledged native injection. Other lane
adapters request bounded daemon scheduling before any native submission; the
daemon starts the next managed run automatically without blocking the sender
on the current run.

Interactive Pi and OMP deliveries now initiate native work while idle. Pi
handles tree and compaction transitions. OMP submits independently tracked
batches through native steer/triggerTurn and correlates exact message and
context events. The other products retain their existing interactive carriers.

A delivery receipt proves acceptance, not model completion. A queued lane
message belongs to the daemon; a queued peer message belongs to its product
owner. Neither queue is durable, and neither receipt permits resending the
message. Capacity failures are explicit and uncertain writes are never replayed.
Native denial, cancellation, shutdown or context reset can prevent completion.

Upgrade federation hubs and daemons together for completion-pointer forwarding;
incompatible links report ForwardLost. Restart product and MCP processes after
replacing their installation so they load the current SDK. Older closed-schema
clients can reject current spawn responses containing policy.trace and disconnect
even after the child opened.

Claude lanes use automatic next-run scheduling. Historical same-turn injection
worked, but acknowledgment independent of a blocked tool batch and safe terminal
handoff remain unproven. No native Qwen OOM fix is claimed.

This file describes v0.5.3 behavior, not publication or completed installed
acceptance. Source tests, artifact verification and permanent-install checks are
recorded separately; successful delivery receipts alone do not establish wake.
