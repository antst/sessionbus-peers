## Runtime behavior and bounded state

The launch suffix is exactly the already stamped outer contract. Empty VALUE becomes `[]`; otherwise split on commas without trimming, deduplication or discarding empty elements, as `sessionbus-call::splitGroups` at b1d7adb. With no suffix export `[]`, not an inherited group value. All preceding argv elements, including native `-n`, `--resume`, `--`, invalid values and `--version`, are passed unchanged. `mcp` is not a magic public-launcher argument. Native errors remain native. `SESSIONBUS_GROUPS` is launch JSON transport, not another user-facing grammar. Child native processes inherit the launch groups naturally (X).

The launcher and owner use the existing daemon socket placement rule/explicit SESSIONBUS_SOCKET, not a Claude-specific socket directory. The JS kit does not export socket path discovery at this revision: port only `bus/sdk/go/internal/stateroot/stateroot.go` at b1d7adb: nonempty SESSIONBUS_SOCKET resolves against cwd; otherwise nonempty XDG_RUNTIME_DIR gives `<runtime>/sessionbus/presence.sock`; otherwise `/tmp/sessionbus-<uid>/presence.sock`, with absolute path resolution. Define this once in `owner.mjs` and import it in `main.mjs`; table-test against the bus function; no discovery attempts or fallback dials. Normal desktop direct-native launches with the plugin but no launch groups use an empty group list, and cannot recover a previous launch name or group. Native `CLAUDE_CODE_MESSAGING_SOCKET` remains the product-owned carrier address.

The owner retains only its current report/acknowledged identity, one connection, one Caller, an integration-ended flag, and cancellation/generation state needed to prevent a late acknowledgment from reviving withdrawn presence. Each report is consumed directly. The synchronous update fixes the intended identity before an async hello; the kit's observed-ack callback installs the matching current generation before further daemon requests are dispatched. Pending acknowledgments for obsolete generations cannot restore them. No history of old sessions, identity message queue or replay of missed hooks is kept. All bus writes use the kit's framing and validation.

Only UserPromptSubmit or usable Stop reports may publish. Session IDs must be actually supplied, not empty/unexpanded template text or public tool arguments; absent/empty/unexpanded optional title means no new title and preserves the known title only for that same ID. Agent-context/Subagent events do not create root presence; consume only the subscribed event shape. Validate native fields against the wire without trimming, renaming or substitute values. Invalid native data produces an integration error. A name change is not a new native session. A different actual native ID invalidates the old delivery context before publishing the next identity.

Matching SessionEnd first invalidates the current delivery context, marks its connection close as deliberate and withdraws it. It does not permanently terminate a healthy resident that may later receive the next session's report after clear. Unexpected connection loss or supersession permanently ends this resident integration, cancels pending Caller work and refuses further publication/tools until a new product-owned process exists. Classify the terminal cause before any async reply/close; handle both fulfillment and rejection of a superseded reply explicitly. Never use the fixture's unhandled finally chain as a production lifetime mechanism. Stdio EOF/output failure/termination closes owned bus/native-write resources; no parent kill, child scanning or native-process reaper is added. Published-owner EOF remains unobserved in native evidence; its code path is tested with a controlled stdio transport.

Public tools require acknowledged current identity. They cannot wait for a future prompt to make the owner ready, fabricate a source, open a second caller connection or call hidden control as a public action. Caller owns its existing explicit start/status/wait handles; the adapter adds no collector, polling, timer or queue. A user-requested Caller wait bound is the existing explicit API behavior, not a reconnection or readiness timer.

The native frame follows D exactly: `msgV:1`, original `msg_id`, `type:user`, `priority:next`, bus-provided source name or source ID in `from`, captured native `session_id`, and `message:{role:user,content:body}`. Preserve the wire body/source; do not trust a source label embedded inside message text or infer a recipient from it. Source-name-to-ID presentation when the sender is unnamed does not invent the recipient's native title.

At receipt of message.deliver, capture the acknowledged native session ID, original bus source/message fields, native socket address and that identity's cancellation context. Never read the later current identity to retarget a pending write. Pre-submission unavailability/refusal may return rejected with the exact boundary stated. Once submission may have occurred, failure/cancellation is Internal `-32603` with valid nonempty string data (for example `uncertain_submission`), which the daemon maps to no_receipt. It is not rejected/closing. Successful write callback returns written; socket EOF supplies no acknowledgment. Clear/rename/supersession cannot reinterpret a completed or uncertain old-target write as a new-target delivery. A per-delivery native socket and its completion/cancellation listeners are needed for that one transfer and are then closed; no native-response wait or resend is added.

Native origin is the product's configured hidden-tool route, not a new authentication protocol. H plus source show exclusion from native model-visible execution; arbitrary malicious stdio/hook configuration and universal subagent provenance are not proved or newly solved here. Such limitations cannot justify a private identity service.

Include these plain sentences with runtime-version citations:

> A Claude peer appears when its MCP owner receives a usable native session report. Until then it is absent from the roster and cannot receive peer messages. Plugin startup can miss a report; publication is not guaranteed at launch, at the first prompt or by the end of that turn. A peer can initially have no name. Native rename becomes visible at the next report that carries the title. A named session quit before any real turn is not resumable by Claude. Sessionbus does not create a turn or write history to make it resumable.
>
> A written delivery means the local write to Claude's native carrier completed. It does not promise retention, admission or consumption. Connection loss ends this integration instance; it does not restart it or terminate the interactive Claude process. A nested Claude session may appear as its own peer with inherited launch groups. Resuming the same native ID in another integration supersedes the old bus connection; Claude can also run external concurrent writers, which Sessionbus does not lock.
>
> Claude can update its installed executable while a session is running, so a parent and a subsequently launched child may run different versions. Sessionbus uses the installed product and does not pin or select a Claude version. The interactive candidate is not a completed Claude lane release.
