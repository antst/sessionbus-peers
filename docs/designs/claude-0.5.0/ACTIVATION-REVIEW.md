## Comparison and remaining decision

1. Always-loaded/inactive MCP was intentional in R2–R4. Our new required native report hooks are a material difference: those old Claude plugins had no hooks. An inactive MCP body does not by itself make ordinary Claude unaffected by globally subscribed hooks, their startup errors or a visible skill directing calls at inactive tools. This is a design edge, not proof that every gated-installed design is impossible.
2. Per-launch whole-plugin loading is a concrete native surface supporting MCP+hooks+skills in source, and removes the need to enable the plugin globally. It does not by itself solve permissions, safe/managed policy, executable binding or nested activation. No per-launch injection is yet selected/stamped.
3. The new code must not resurrect R2/R3 host attestation/PID ancestry or a private profile merger solely because it existed previously. R06 is activation, not native-session identity authority; the settled report remains required.
4. Existing NP01/FP01/FP03/FP05 use installed-global fixtures. They do not prove a per-launch package. Plain child `claude` under that historical topology is not evidence that a new plain child must implicitly join. The revised activation requirement must state that boundary explicitly.

Before selecting per-launch loading, one released comparison must establish: ordinary Claude has no unintended bus publication/tools/requests; managed launcher loads the exact plugin and skill; hidden hook reaches the intended resident; the public tool is actually invoked under the intended native permission policy; explicit native denial stays authoritative; unrelated plugin/tool approval and user configuration remain unchanged. Record existing plugin inventory first, including conflicts, and actual native argv and origin-qualified tool names. Do not use a fake home, manually run the MCP as the success path, grant all tools/bypass permissions, or infer permission from tools/list. Reuse completed controls where they bind the same native/package path; do not launch broad new probe matrices by default.

No native execution is released here. Dev1 can continue independent source/tests; activation implementation remains held until the concrete comparison/proof is sequenced. The existing five-module package inventory is not expanded by this investigation.
