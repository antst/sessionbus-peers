## Selected structure

The same public `claude-peer` dispatches by the daemon launch token: absent means the accepted native-exec interactive path; present means a retained Go worker using the public Go kit Worker and its one Caller. The worker directly launches native Claude in persistent stream-json mode. It inherits the daemon-owned process group; it must not detach the native child or create another process group. No Claude-specific daemon, Node runtime, manager, native-session lock or session registry is introduced.

The worker binds one private report/tool endpoint before native spawn. The product-kept MCP process is the existing binary's private `sessionbus-mcp` alias, selected as a lane forwarder by explicit lane endpoint metadata. It forwards public calls and the common hidden reports to the sole worker; it does not hello, instantiate a second Caller or own lane presence. The SDK consumes/unsets the daemon token during worker startup: do not depend on that token remaining in the child's environment and do not pass a reusable worker token to the native child. The public entry still uses the token; child forwarding uses the worker-created endpoint capability.

Reuse the accepted Go MCP protocol/action/cancellation implementation. A lane backend implements its existing owner interface against the worker Caller and native reports. A byte-stream MCP bridge is preferable to another independently implemented RPC protocol. The initial command hook is a short-lived invocation of the same binary through a private hook alias; it submits the native SessionStart report to that same endpoint and exits. It introduces neither another resident process nor another endpoint. Bind the initial report's native CLAUDE_PID to the directly spawned native PID, retaining OB01-R1b's exclusion of nested emitters/agent reports. Endpoint access is scoped to a fresh worker-owned private directory/capability; no session-ID-based unlink or takeover of an existing endpoint.

The plugin is still loaded per launch from the real installed package. Common hooks remain exactly UserPromptSubmit/Stop/SessionEnd via hidden `native_identity_event`; lane adds only its SessionStart command hook through native launch settings. No duplicate prompt/Stop/End command hooks, native-settings merger or global dummy MCP. Plain `claude` and unconfigured plain nested `claude` remain ordinary. Explicit integration of another child is a new `claude-peer` launch under the already documented rules.

## Native control and truthful results

`session.open` passes the protocol's composed native name part, exact resume ID and typed settings to native flags, followed by caller arguments in their original order. Preserve the accepted activation prefix and native `--` behavior. Do not carry over held R5's default-to-dontAsk substitution, broad tool allow, private argument allowlist or manufactured unsupported-value errors. Native config/policy may make the required boundary unavailable; report that boundary, without restoring suppressed tools/hooks. The daemon owns composition/resume recipes; the adapter does not infer titles or match names.

Before returning OpenResult, require the matching initialize success, the root's settled SessionStart identity/title report, and the required native integration-tool/config readiness. Retain one current report if it precedes initialize, not a report queue. Do not mint a native ID and return it as authority. A supplied native ID, if explicitly requested, is still only a request until native confirmation. Fresh no-supplied-ID open and this complete installed composition remain OB03 acceptance conditions. Open failure cleans resources allocated before success; the current kit only calls product Close after successful open, so Open must own its unsuccessful cleanup. No dummy prompt/history write. Resume requires the already-amended at-least-one-real-turn condition.

Each explicit run has one generated **message correlation UUID**, not a generated native identity. Native input echo/replay and result `user_message_uuid`/`user_message_uuids` bind the run. Honor `is_error`, terminal reason and stop reason together; subtype success alone is not success. An empty zero-turn append result without the run UUID is not its terminal. Result boundaries and multiple UUIDs retain the exact login ledger limitations.

Lane delivery uses native `shouldQuery:false` staging, not interactive msgV1 idle wake-up and not a new explicit run. Return `queued_for_next_turn` only at the demonstrated native staging/replay boundary, never on write completion alone. Preserve the distinction between staged context and model consumption. If a write may have occurred but native admission is not established, retain uncertainty under the existing protocol; do not call it rejection. Do not wait on an adapter tool/permission barrier whose release depends on the same replay being awaited: the earlier active-append probe was circular. Active and terminal-boundary admission remain concrete open rows; no universal supported/unsupported conclusion is inherited from that failed harness.

Interrupt uses one correlated native control request per kit-coalesced interruption. The bus acknowledgment records the request; only a UUID-bound native terminal sets outcome. Close, native EOF and native death must settle the active run and pending controls truthfully, including when no native result exists. Do not fabricate a successful native terminal. Use the shared SDK's public APIs; a demonstrated generic SDK close/cancellation defect belongs in a bounded shared SDK correction, not a copied Worker or wrapper cache.
